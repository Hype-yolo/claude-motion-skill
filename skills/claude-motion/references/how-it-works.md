# 从一句题目到成片

Claude Motion 是 Agent 创作时读取和调用的一组本地文件。GPT 仍然负责理解题目、选择方案、写新代码和检查画面；包内实现让它不必从零猜测每一种造型、材质和动作。

## 包内各部分负责什么

| 部分 | 实际内容 | 作用 |
| --- | --- | --- |
| SKILL.md 与 references | 使用规则、目录、接口、来源、已知缺口 | 帮 Agent 选择和使用资源 |
| 47 条案例目录 | Lemo 43 套、ReelMimic 4 套的选定源码 | 提供绘图、材质、角色与运动实现 |
| 5 套制作系统 | hd2d、papercut、handdrawn、glass、swiss，合计 10 个开发示例 | 复制一个已经接通的工程后改编 |
| 14 个场景入口 | 11 个既有入口、3 个实验组件；部分与案例目录重合 | 提供场景结构及可修改的时间线 |
| 30 个物件包 | 27 个外部模型、1 套既有产品几何、2 个本地模型 | 补足真实物件结构，部分带骨骼动作 |
| 20 个源码组件（17 个既有、3 个本版新增） | 蜡笔、信号、建筑、浅水、工作室、车辆、水彩、笔触、步态等实际实现 | 创建可编辑工程，保留原绘制/材质/动作能力 |
| scripts | 检索、复制、校验、导出 | 处理可重复的工程操作 |

这些数量有重合，不能相加作为风格总数。一个模型可以在多种画面中使用，同一案例也可能有多个制作入口。阅览室场景另附 14 个家具文件，不额外计入 30 条物件目录。

素材没有全都“变成提示词”。有的是 JavaScript 绘图代码，有的是 GLB 网格、骨骼、贴图，也有预览图和许可文件。预览帮助判断，源码和模型参与实际绘制。生图是可选辅助手段，默认不要求。

## 1. 把题目转换为画面与动作需求

以“守塔人修好灯塔，小船回港”为例，需要海面、灯塔、故障排除、旋转光束、小船移动及前后因果。Agent 先识别这些需求，再判断二维印刷、微缩三维等表现方式是否合适。

查找使用 `route.mjs --query`。它是中英文标签检索，不是另一个训练过的美术模型。案例分数按材质、动作、场景、形式、题材等标签加权；返回的 `score` 不是美感分数或成功概率。场景、物件和制作系统另返回候选列表，不是保证能一起使用的组合方案。没有匹配时，可按视觉需求改写查询或查看完整目录。

## 2. 看候选的真实实现，选一个主方向

Agent 阅读风格说明、示例和相关函数，查看可用预览，检查依赖。默认选择一个主案例，必要时另补一个。不要把排名第一当成自动答案，也不要把“卡通”“纸纹”当成通用质量提升。

整支片先统一轮廓、比例、配色、材质、光照和运动规则。一个写实狐狸和一个像素房子即使分别好看，也可能不适合放在同一场景。

47 个源码条目中有 36 个原例预览、11 个存在预览缺口。缺原例预览不代表完全不能用其中某个模块，但必须检查新作品中的实际渲染，不能声称已复现原片。

## 3. 复制可用代码与素材，建立新工程

- 原案例：`prepare-case.mjs --case <id> --out <新目录>`。
- 制作系统：`create-engine.mjs --engine <id> --out <新目录>`。
- 场景入口：`create-scene.mjs --scene <id> --out <新目录>`。
- 源码组件：`create-extension.mjs --extension <id> --out <新目录>`，按输出中的对应命令导出。
- 物件检视：`create-model.mjs --model <id> --out <新目录>`。

这些工具复制代码和相关资源，保留署名与来源，并在有清单时校验哈希。它们本身不会理解故事，也不会自动把旧片改成新片。模型检视工程仅用于确认物件，仍须把模型接入故事中的位置、动作和镜头。

## 4. 保留绘制能力，重写故事

可保留的是真正产生效果的实现，例如纸张负形、墨色合成、金属反射、景深、关节和步态。Agent 按新题目改写主体、几何结构、动作、镜头和节奏。

现有灯塔成片调用了 Lemo 浮世绘案例的印刷实现，但守塔人、灯塔故障和船回港的事件重新编写。光圈片借用了玻璃产品案例的影棚、反射和金属处理；库中没有同款光圈，八片叶片、壳体与开合逻辑由新代码建立。山顶包裹片则调用完整货车 GLB，再重写山路和投递故事。

这几种用法都允许。复用比例根据题目决定，不能把所有新片说成完全从零创作，也不能将原片换标题当成新故事。

## 5. 库里缺东西时补结构，保持画风

优先考虑：用现有部件组合、按同一套规则写新几何或绘图路径、引入许可清楚的外部模型。2D 对象不必强行建成 3D；需要空间遮挡、镜头绕拍和结构演示的对象才考虑三维。

新对象要协调尺寸、比例、线条、材质、光照和动作节奏。静态 GLB 不会自动走路；已有跑步动作也仍需编排位移和脚部接触。导出器没有自动防穿模、碰撞求解或自动美术统一功能，接触和遮挡需要检查、修正。找不到合适实现时说明缺口，不能靠突然更换风格掩盖它。

## 6. 检查代表片段，再完成时间线

先查看主体造型、关键动作与材质实际呈现，再扩展整片。重点跟题目走：翻书看纸张和书签，抓取看接触与释放，机械结构看轴心和联动。标题、标签不能替代动作表达。

这是一项创作检查要求，不是已证明能单独提升美感的复杂制作流程。当前不强制加入此前消融实验没有证明有效的额外步骤。

## 7. 导出与交付

浏览器按绝对时间逐帧绘制，FFmpeg 编码 MP4。时间跳回同一点应得到相同画面；外部资源须先放入工程。导出器检查重复寻帧、浏览器报错和视频解码。音频通过 `audioWav()` 提供，没有该接口就无声。

交付可编辑代码、MP4、预览和 ADAPTATION.md。制作说明列出来源、实际调用、改写内容与验证边界。技术检查通过表示视频可用，审美效果仍应看成片。

## 它如何在新对话中起作用

新对话调用 Skill 后重新读取入口，按需检索包内文件、运行代码，再生成作品。可迁移的是外部资源和操作方法，没有更新 GPT 权重；删除或不调用这些资源时，也不能保证保留相同效果。这个项目希望减少从零绘制的粗糙感，效果取决于选型、实际复用和改编质量。
