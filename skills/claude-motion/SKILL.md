# Claude Motion

默认采用**案例辅助创作**：先找到适合题目的真实实现，再改编。只读文字方法后从零画几何图形，不等于使用了这个案例库。名称表示用户希望接近的视觉方向，不保证模型身份或审美效果。

分别检查风格辨识度与画面完成度；能认出使用了案例不等于作品更好。默认先用案例源码，不把新增生图设为必需步骤；需要明确造型或用户要求时再加图。现有定性比较支持这一默认路线，但尚未证明跨题材稳定提升，也不意味着所有题目都应套同一种画风。

v0.4.0-beta.1 收录 47 套源码案例；36 套有原例抽帧，11 套预览不可用。抽帧多数使用字体回退，不等于完整影片或音频验证。安装、各案例状态及依赖见 [安装与验证](references/installation.md) 和 [案例状态表](references/case-status.md)。

完整的输入、检索、选型、改编、补缺和导出逻辑见 [工作原理](references/how-it-works.md)。首次使用或向用户解释机制时读取。

## 选择实际案例

运行 `node <skill>/scripts/route.mjs --query "<用户题目>" --limit 5`。结果来自 [案例目录](references/case-catalog.json)，包括来源、适用场景、源码路径、素材缺口与预览状态。题目未指定风格时，结合角色动作、空间关系、叙事跨度和材质选择，不只匹配题目中的一个名词。关键词排序是查找帮助，不替代视觉判断；可以改写为视觉需求再检索，或用 `--list` 查看目录。

读候选的 styleGuide、demoGuide 和相关绘图模块，查看可用预览。选一个主案例，确有必要时补充第二个。先运行最关键的绘图机制，确认它在当前环境下真实可见。未运行的样片不能声称已复现；缺少字体、图片、三维依赖的条目要先补齐合法依赖或选别的案例。[来源索引](references/source-index.json) 含更广的研究清单，**索引条数不等于可调用案例数**。

用 `node <skill>/scripts/prepare-case.mjs --case <id> --out <作品目录>` 复制选定案例及公共代码，保留许可证和来源清单。命令支持逗号分隔的多个 ID。它复制源码，不自动安装依赖或补齐缺失素材。完整原片只作为参考；不要把原片换标题或直接截取其片段当成新创作。

## 优先检查已接通的制作组件

包内提供 **5 套可运行系统、10 支开发示例**：像素三维、剪纸、手绘角色、玻璃实体、字体图形。原来的两支试片已获用户认可；扩展片已有负反馈：第 1、2 支场景/角色不协调，第 7、8 支物体与运动质量被否定，第 5、6 支不能凭 Clawd 角色认定 Claude 感。保留原片记录；修订版仍待评价。它们与 47 个源码案例是不同统计口径。

先运行 `node <skill>/scripts/route.mjs --engines` 查看组件与适用边界，再用 `node <skill>/scripts/create-engine.mjs --engine <id> --out <新目录> [--example <名称>]` 创建独立工程。用真实预览和主体/动作需求选择，不因有组件就强制套风格。具体入口、原机制、修改位置与限制见 [制作组件与验证](references/production-engines.md)。手绘示例复用原 Clawd 角色，不能称为原创角色模型。生成器给的是完整示例；新题目必须改写主体、事件和镜头，不能仅换标题。

## 新增可直接创建的场景

`route.mjs --scenes` 列出 11 个既有场景起点和 3 个实验候选，题目查询同时返回 `sceneCandidates`（默认排除实验候选）。既有入口中 7 个是 animate 来源示例，4 个是已收录 Lemo 案例的组件适配；与旧 47 条目录有重合，不能直接相加当作风格数量。用 `create-scene.mjs --scene <id> --out <新目录>` 创建完整可编辑工程。人物手绘、咖啡馆、立体纸书、低模海岛已接通实际结构；animate 提供素描、排线、孔版、等距线描、像素、彩纸和数学图形。查看 [场景入口与边界](references/scene-library.md)。

这些入口优先解决“源代码收录了、但生成时没真正用到”的缺口。须查看原例、按主体与动作挑选；不默认只用一套画风，不用吉祥物替代风格判断。原例预览不能冒充新题材成片；海岛示例保留原事件，只有正常改编后才可交付为新作。本轮技术验证通过不等于用户已认可其 Claude 感。

## 新接通的源码系统

本版共20个可调用组件，其中17个既有组件：包含此前的蜡笔、信号图解和参数建筑，以及雨夜城市、浅水、工作室、体素、车辆动力学、水彩运输、应用发布、霓虹线场、四墨印刷、GPU笔触、居民关节、昆虫、像素鸟与人物步态。运行 `route.mjs --extensions` 查看；题目查询返回 `extensionCandidates`。用 `create-extension.mjs --extension <id> --out <新目录>` 创建完整工程，按返回的命令导出。实际保留机制、固定来源和依赖许可见 [新增源码组件](references/source-extensions.md)。每项已导出一个18秒的新题材开发片；不计作17种新画风，原47条案例口径不变。信号、建筑和第14轮七题获用户选入[公开对照展示](https://hypeyolo.com/motion/)，不据此声称全题稳定提升；其余题目未选入展示。Lanshu只接V2，Remotion依赖不是MIT；车辆排除上游未授权Collect模型。

## 本版新增：机械、动物与手绘纸艺

在前版 17 个组件之外，v0.4.0-beta.1 另接入 3 个组件（合计 20）：`anatomy-mechanisms` 的投影零件、拉伸与面着色；`procedural-animals` 的程序化动物造型、骨架、步态与接触动作；`anidoodle-paper` 的水粉纸张、折面及纸纤维绘制。使用相同 `route.mjs` / `create-extension.mjs` 入口。适合机械结构、动物运动或二维纸艺题目时再选，不强制所有题目采用新增画风。

三项均已有一个 18 秒全新题材成片，另与扩充前冻结的 Skill 做第 15 轮对照。用户确认狐狸片质感明显提升；机械、纸艺因二维/三维表现不同而暂按不相上下，不计作已验证收益。狐狸片评价不外推到全部动物或题目。具体固定提交、调用位置、许可和限制见 [本轮新增组件](references/source-expansion-15.md)。动物组件自带兼容的 Three.js，避免替换其他组件的运行库；纸艺只带许可明确的代码，不带上游例外媒体。

## 先找具体物体与动作

另有 3 个定向补缺的实验组件：完整阅览室、抓取放置机械臂、二维植物墨线。需要这些能力时，可用 `route.mjs --query "<题目>" --include-experimental` 查看，再用 `create-scene.mjs` 创建。它们已接成新题材开发试片，对照未证明三者均有稳定收益，不默认推荐，也不计入 Claude 风格数量。接口和边界见 [定向组件](references/targeted-components.md)。

用 `route.mjs --models` 或题目查询中的 `modelCandidates` 查找完整模型。`create-model.mjs --model <id> --out <新目录>` 提供带署名的可运行检视工程。30 个物件包中包括 27 个外部 GLB、1 套原案例完整产品几何、2 个本地修订模型；这不增加 Claude 风格案例数量。详细接口与来源见 [模型库](references/model-library.md)。角色身份不是风格依据；使用 Clawd、狐狸或像素人物都须匹配故事、画面比例和材质。

近期成片反馈见 [已观察到的效果边界](references/observed-feedback.md)：主体模型补足造型可能有效，强加排线、纸纹或卡通画风不一定改善成片。先判断题目的结构与动作缺口，再决定借模型、借绘图机制，或只使用其中一类。别为了显示 Skill 存在而强套画风。

## 保留什么，重新写什么

保留产生视觉特征的**实际实现**：造型路径、排线或笔触、印刷合成、角色关节、遮挡与透视、运动节奏等。可原样调用、参数化或在署名下改编。不要只提炼颜色、加一层噪点，就丢掉原本让画面成立的结构。

尤其检查材质合成器、轮廓绘制和角色动作是否真正被调用。同样写着“木刻”，保留原版印刷合成与只借排线会得到不同结果；参考图的配色不能自动成为删掉原机制的理由。制作说明写清实际保留、替换和舍弃了什么。

先确定整片共用的轮廓、比例、材质、色彩和运动规则，再选择物件。缺少模型时，优先用现有部件组合或按相同规则新建；复杂主体也可引入许可清楚的外部素材，再统一尺寸、材质和动作。需要外部服务或新增生图时遵守用户授权。找不到合适对象就说明缺口，不临时换整支片子的画风，也不把不相关角色硬塞进去。

根据新题目重写物件、人物关系、故事事件、构图和镜头。复用角色或场景资产时在制作说明里明确指出。跨时代或跨场景的题目需要多个可辨认的视觉状态和真实动作，不能只用标签替换表达发展。镜头需留出观看细节和动作结果的时间。

先做一段有代表性的画面和动作，检查主体轮廓、材质层次、景深/遮挡、接触与运动连接；有问题先改到可用，再扩展整片。检查时临时隐藏标题：若标题一去掉就只剩几何示意，继续完善主体绘制。参考作品可以用于正常创作审查，这个模式不是“闭卷”。

`assets/runtime/` 是本项目较轻量的辅助工具，API 见 [runtime.md](references/runtime.md)；它们不是所选案例的替代品。[direction.md](references/direction.md) 是可选构思辅助，不要求把每条规则都套进影片。

## 导出和交付

作品目录提供 `scene.js`，导出 `width`、`height`、`duration` 和 `render(ctx,t)`；可选 `ready`、`audioWav()`。可以使用 Canvas、离屏 WebGL、局部缓存或静态绘画层，不限于几何图形。资源在作品根目录内，按任意时间确定性绘制；具体接口见 runtime.md。

原生页面工程可用 `--page index.html`，需提供 `READY`、`DUR`、`render(t)`、最终合成画布 `CAPTURE` 和可选 `audioWav()`；这个入口保留原生 WebGL 渲染。

先抽帧检查，再运行 `node <skill>/scripts/render.mjs --root <作品目录> --out <作品目录>/film.mp4 --fps 24`。需要 Node 22+、Playwright Chromium、FFmpeg（含 ffprobe）。在 Skill 目录执行 `npm ci` 和 `npm run setup`；导出器优先使用 Skill 自身安装的 Playwright。依赖解析可通过 `MOTION_PLAYWRIGHT_MODULE` 指向已有 Playwright。无 audioWav 就没有声音；不要把无声片称为有声片，也不因聊天语言擅自添加中文字幕。

交付源码、MP4、可播放的本地预览和简短 `ADAPTATION.md`：列出来源/提交、保留与改写的实现、使用的资产与许可证、实际检查和未解决问题。来源归属是作者声明，不冒充已审计的模型调用。技术通过不等于“已达到 Claude 感”。不自动公开发布。

## 隔离比较

用户要求比较时，先冻结此 Skill，再用全新上下文生成 Skill 版；无 Skill 版只给相同题目、技术规格与中性导出器。两边使用相同模型设置和允许的自查次数，不给无 Skill 版负面风格指令，不泄露另一组画面或用户偏好，不替它故意简化。开发试作和正式结果分开，首次正式结果封存；发现效果不佳如实保留，修订另开版本。

用户明确要求“闭卷/仅方法”时，切换回方法模式并禁用案例源码、预览和资产；不能把案例辅助的收益称为无参考迁移，也不能从单次对照推断普遍提升。
